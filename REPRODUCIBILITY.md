# Reproducing the reported experiments

This document separates rebuilding the published displays, running new experiments, and checking the
implementation. For installation, the manuscript-to-file map, and the full experiment commands, see
[README.md](README.md). Figure numbers can change during manuscript editing; asset names and result
directories are the stable identifiers.

## Choose the scope

| Task | Inputs and command | What it establishes |
|---|---|---|
| Rebuild figures and numerical tables | Included compact results; `plot_figures.py` and `make_tables.py` | The displays and aggregates can be reconstructed from the retained records. This does not rerun randomization tests. |
| Run an experiment from scratch | Recorded design and seeds; the appropriate runner; provider files for real data | New randomization calculations that can be compared with the retained results. This can require substantial CPU time. |
| Check the implementation | `python -m pytest -q` | Statistical oracles, search/configuration checks, and selected small replications. Passing tests do not establish a fresh replication of every reported experiment. |

Run commands from the repository root after installing `requirements-frozen.txt` as described in the
README. To rebuild into a new directory without replacing the supplied figures and tables:

```bash
repro_out="$(mktemp -d)"
python plot_figures.py --out "$repro_out/figures"
python make_tables.py --out "$repro_out/tables"
```

With only distributed inputs, the plot command regenerates 15 statistical PDF assets. Two further
assets are supplied separately:

- `fig_real_actg175_2d_regions.pdf` is supplied, and copied or preserved when the individual-level
  plotting arrays are absent. To regenerate it, obtain the ACTG provider data and follow the
  `--two-covariates-only` / `--actg-scatter-input` commands in the README. The arrays are local only.
- `figures/knn_boundary_cap.pdf` is an author-drawn geometric schematic, not a simulation output;
  it remains available as the supplied asset and is not generated by the plot command.

## What is retained

| Analysis | Included result directory | Runner |
|---|---|---|
| Main uncentred/centred comparison | `results/centering_comparison/full_integer/calibration/centre10/` | [run_calibration.py](runners/run_calibration.py) |
| Separate two-region diagnostic | `results/calibration/two_regions/` | [run_two_regions.py](runners/run_two_regions.py) |
| Additional simulation designs | `results/supplementary/<experiment>/` | [run_supplementary.py](runners/run_supplementary.py) |
| Method timings and Gaussian warm start | `results/timing/{methods,warm_start}/` | [run_timing.py](runners/run_timing.py) |
| ACTG and writing data | `results/real_data/{actg,noy}/` | [run_real_data.py](runners/run_real_data.py) |
| Full-integer GGL analysis | `results/real_data/ggl/` | [run_ggl_integer.py](runners/run_ggl_integer.py) |

Simulation `details.csv` files retain per-repetition scalar results, including the bounds and
configuration needed for aggregation; `run_meta.json` files describe the runs. Real-data files retain
summary statistics, stability or robustness calculations, and aggregate display pieces. The
[presentation manifest](results/presentation_manifest.json) records source hashes, compact-file
transformations, and figure/table inputs. Its `work/...` source paths identify author-side archives,
not directories included in a fresh checkout.

Full evaluated p-value paths and large checkpoints are **not distributed**. The paths recorded by
the main calibration, two-region, shared-versus-conditional and real-data runners are retained in
the original run bundles and can be regenerated with those runners. The other experiments retain
their own summaries and do not uniformly store complete paths. Rebuilding the compact summaries
does not reconstruct omitted paths. Provider data, prepared GGL assignments,
and ACTG point-level arrays are also excluded; see [data/README.md](data/README.md) for acquisition
instructions and file checksums. Do not add these files to Git.

## Statistics and candidate sizes

The main comparison uses the same original outcomes, assignments, and Monte Carlo draws:

```text
raw:       sum_{i in B} (Z_i - pi) Y_i
adjusted:  sum_{i in B} (Z_i - pi) (Y_i - mean_B(Y))
```

There is no OLS fit in this comparison. Its metadata records `ols_adjustment: false` and explicit
statistic names. The API and real-data analyses use the centred statistic. ACTG's `change` outcome
subtracts baseline CD4 from the 20-week count; it is not an OLS residual.

Legacy field names in the separate supplementary diagnostics have different meanings: `raw` there
means the centred statistic on original outcomes; `indep` in stress and `adjusted` in the two-region
records refer to independent OLS residuals. Stress also has an in-sample OLS diagnostic. Read each
run's configuration rather than applying the main comparison's label convention to every file.

The revised primary analyses use the full integer candidate domain `1, ..., n`. Descending search
can stop at the largest non-rejected size after checking every larger integer size. An evaluated
path shorter than `n` is therefore not evidence of a sparse candidate grid; this stopping rule
does not assume p-value monotonicity. Bisection in the timing comparisons queries integer sizes
but relies on the paper's monotonicity condition. Historical `--grid paper` runs are separate
reproductions of the former sparse-grid setting, not the source of the revised primary bounds.

## Running and comparing new experiments

Use the [from-scratch commands](README.md#run-experiments-from-scratch) for the full configurations,
including the timing series and staged GGL search. Use fresh output directories for new runs;
keep the distributed results as the comparison target. The from-scratch commands write to ignored
`results/reproductions/` directories. The ACTG scatter example uses the separate ignored
`results/real_data/actg/local/` directory. A smoke run exercises a smaller
configuration and is not a replacement for the paper's repetition counts and sample sizes.

Record the code revision, provider checksums, command, output directory, software environment,
CPU/thread settings, and seeds. Compare the run configuration and statistic identities before
comparing bounds or aggregating results. Seeds alone do not ensure bitwise agreement across
linear-algebra environments; supplementary OLS diagnostics are particularly sensitive to this.
The recorded environment and numerical tie rules should be preserved when exact agreement is needed.

The test suite includes direct statistic calculations on small examples and selected retained-result
replications; [test_results.py](tests/test_results.py) makes the latter scope explicit. It does not
rerun the full GGL analysis or every Monte Carlo repetition. The retained convergence-rate,
effect-size, and timing series already used integer sizes and were not rerun as part of the
centring/sparse-grid correction. These checks cover the implementation and selected retained results;
they are not a rerun of the full experimental suite.

## Implementation details relevant to interpreting the paper

- **Timing.** The one-dimensional shared evaluator uses compensated prefix sums. The two-dimensional
  evaluator stores neighbour orders and updates compensated running sums as the queried size changes;
  it does not materialize cumulative statistics for every centre, size, and draw. See
  [search.py](zeroreach/search.py) (`Shared1D`, `Shared2D`) and [kernels.py](zeroreach/kernels.py).
  The [timing runner](runners/run_timing.py) includes neighbour-order construction, assignment draws,
  evaluator setup, and search. Data generation and numba warm-up are outside the timed section.
  Reported CPU seconds depend on hardware and thread settings.
- **Writing data.** Date checks use the provider's `startdate` fields normalized to calendar days.
  The participant filter excludes a participant whose earliest recorded session as a grader predates
  that participant's task-survey date. A separate grade-level filter removes a grade when its session
  date is later than the grader's own task-survey date, where that date is available. These are
  distinct ID/date checks, not a comparison of essay-submission or task-completion timestamps.
  See [realdata.py](zeroreach/realdata.py) (`load_noy`, `_grade_means`) and
  [data/README.md](data/README.md) for the remaining exclusions and outcome construction.
